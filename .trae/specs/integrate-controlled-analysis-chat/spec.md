# 聊天接入完整文件统计规格

2026-11-02；状态：已完成本机实施与验收；2026-11-03 已随 `3d0fe2b` 推送，未部署。
承接 `deliver-controlled-analysis-slice`，两轮代码与验收记录一并归档。

## 为什么

完整文件列求和已具备后端接口，但聊天仍只能调用文本预览，用户尚不能在对话中取得
同源统计结果。下一轮接通“受管附件 → 指定列求和 → 结果与来源 → 校验后下载”，
同时修正会使失效文件或未完成工具被当成成功结果的调用路径。

## 本轮变化

| 能力 | 用户可见结果 | 范围 |
| --- | --- | --- |
| 统计工具 | 明确文件与列名后，在聊天中计算完整文件的列和 | 复用现有 Decimal 计算，不增加指标 |
| 统计结果卡片 | 看见精确值、行数、缺失/重复警告和来源 | 不随“隐藏工具详情”消失 |
| 校验后下载 | 下载与卡片一致的 JSON，失效来源给出明确提示 | 使用现有统计 REST 接口，无新持久产物 |
| 真实工具状态 | 未完成、失败或取消的调用不再补写为成功 | 按 `tool_call_id` 匹配实际结果 |
| REST 缓存准入 | 文件相关调用每次执行当前来源检查 | 新缓存策略隔离旧条目，普通无工具问答仍可缓存 |

本轮不增加图表、SQL、任意代码执行、指标配置、后台任务或报告存储。
不调整上传支持范围、数字精度、生产部署、模型价格或已有资源限额。

## 新增要求

### R1 统计工具复用唯一数值来源

系统应注册 `analyze_file_statistics`，模型可见参数仅为规范 UUID `file_id`
和 1–128 字符的 `column`；不接受 owner、路径、表达式或可扩张的预算参数。
指标固定为 `sum`。用户未说明列名或多附件存在歧义时，先澄清，不自动选择首列或首文件。

工具从服务端执行上下文取得主体，重新读取用户/角色，调用现有文件服务；
每次执行均复核 owner、有效期、大小、SHA 和受管路径。
普通文档预览仍使用 `analyze_document`；完整列和不得由预览、模型或浏览器重算。
父图和内联子图均可调用同一工具，统计工具本身不发模型或搜索请求。

成功消息采用小型版本化外层结构：
`type=managed_file_statistics`、`version=1`、`status=success`、
`data=<现有统计接口完整 payload>`。`data` 不增删字段或改变数值编码，
保留原 `analysis_version`、`parser_version` 与 `result_sha256`；
外层版本用于聊天协议，不改变上一轮 canonical hash 算法。
失败结构为同一 `type/version`、`status=error`、`error.code` 和安全提示，
不携带 `data`。权限及不可见文件沿用统一不可见语义，未知异常不暴露内部细节。

#### 场景

- **当**用户提交完整 CSV/JSON 并要求指定列求和，**则**实际工具结果与同主体、
  同来源、同参数的 REST 结果及独立数值参考一致，包括超过预览上限的尾部。
- **当**列不存在、目标列非数值、来源失效或调用越权，**则**返回稳定失败，
  不退回预览求和、不展示数值成功卡片。

### R2 工具执行保持既有预算和生命周期

工具执行前进入现有合计工具账本，失败执行也扣额；父子图、并行分支与重试
共用同一次 run 的限额，第 13 次工具执行不得读取文件。
保留默认模型 8 次、工具 12 次、run deadline、身份隔离及单次租约释放合同。
复制图、`with_config`、四种调用面不得绕过这些限制。

同步文件读取和计算不得直接阻塞异步事件循环；等待方式沿用受控线程或现有工具
异步适配，证明并发容量有界。现有 5 秒期限是解析/遍历检查期限，不承诺强制抢占
已进入的同步读取或解析器。run 取消/超时后不得发布新的成功消息、缓存答复或派生产物；
已经完成且已交付的工具结果只代表那次计算，不代表整个 run 成功。

#### 场景

- **当**父子图并行调用统计工具并耗尽合计预算，**则**无越额读取、身份串用或额外模型发送。
- **当**计算等待期间取消、超时或关闭流，**则**run 使用既有稳定状态结束，
  清理与租约释放仍可核验，重试使用独立 run 状态。

### R3 对话展示统计结果与来源

仅从实际 `ToolMessage` 渲染统计卡片，关联其 `tool_call_id` 与统计工具调用；
校验外层版本、成功状态及内部必要字段。普通模型文本、合成补齐消息、未知版本、
缺失字段或损坏 JSON 不得冒充成功卡片。
统计卡片是业务结果，始终可见；“隐藏工具详情”只控制通用调用细节。
按 tool call/message 身份去重和排序，流式更新、刷新及切线程不重复或串用卡片。

卡片保留数值字符串，禁止经过 JavaScript `Number`、浮点格式化或再次累计。
默认展示列名、精确和、总行/有效/缺失/重复数及质量警告；来源详情可折叠，
展示 UUID、文件 SHA、结果 SHA、解析/分析版本。单位使用“未指定”。
固定模板说明来自同一 `data`；模型正文可补充解释，但不作为数值和成功状态来源。

交互布局如下；沿用现有聊天组件风格，不增加独立分析页面：

```text
┌ 完整文件统计 · 求和                         计算时快照 ┐
│ 列：amount        合计：<精确十进制字符串>            │
│ 总行数 / 有效数 / 缺失数 / 重复行数                 │
│ 质量提示：缺失不参与计算；重复行保留；单位未指定      │
│ [查看来源]                    [校验来源并下载 JSON] │
└────────────────────────────────────────────────────┘
```

错误/未知状态用文字说明，不能只靠颜色区分。按钮支持键盘和明确的焦点/禁用状态；
窄屏换行，长数值与摘要可横向查看或展开，不通过截断改变可取得的原值。
文件名、列名及错误文本按文本渲染，不作为 HTML 或任意下载 URL。

#### 场景

- **当**用户隐藏工具详情、刷新对话或切回旧线程，**则**有效统计卡片仍保留，
  明确标注“计算时快照”，不自动宣称源文件当前可用。
- **当**消息尚未完成、工具失败或协议无法识别，**则**显示对应状态或安全退化内容，
  不将模型的文字答案包装成确定性计算结果。

### R4 下载重新验证当前来源

“校验来源并下载 JSON”复用固定 FastAPI Origin 上的
`POST /api/files/{file_id}/statistics?download=true`，使用卡片中的列名，
通过现有认证客户端携带 JWT 和请求 ID；不使用模型或工具消息提供的 URL。
下载前校验返回结构，并要求来源 UUID/SHA、参数、版本及 `result_sha256`
与原卡片一致。只有一致时才创建下载；下载名由受控 UUID 组成。

请求中禁止重复点击。成功、失败和中止后释放 Blob URL/请求资源。
切线程、退出登录或组件卸载时取消请求并丢弃迟到结果；不得向新主体交付旧下载。
401 沿用退出认证流程；404 显示“源文件已不可用”；完整性错误提示无法校验；
网络错误允许手动重试。结果或版本变化提示“结果已变化，请重新分析”，
不静默替换原卡片或下载另一版本。

历史卡片与用户已取得的本地副本属于已授权计算时快照。删除、过期或漂移
阻止新的统计/下载，不回写或抹除已有对话，不自动重新计算历史卡片。

#### 场景

- **当**源文件仍有效且结果未变，**则**下载 JSON 与卡片 canonical 结果一致。
- **当**源文件在首次计算后删除、过期、漂移或版本变更，**则**下载拒绝或要求重新分析，
  保留原历史卡片，不能输出旧成功缓存来绕过当前校验。

## 修改要求

### R5 REST 回答缓存采用保守准入

`AgentService.ainvoke` 的缓存保留当前主体/模型/配置隔离，采用新的策略命名空间。
旧策略条目即使仍在 24 小时 TTL 内也不再命中；不执行 Redis 全库清理。
明确包含受管文件引用的请求绕过回答缓存读写；其他请求仅在服务端确认
该 run 没有执行任何工具且正常完成时，才允许写入回答缓存。
因此搜索、内置工具和子 Agent 参与的 REST 答复本轮也不缓存；
独立搜索工具自身的缓存不变，普通零工具问答保留缓存收益。
代价是工具型 REST 问答的重复请求可能增加执行耗时和模型调用次数，
仍受原有单次 run 预算约束；以后有明确收益时，再单独设计依赖可复核的回答缓存。

缓存资格由服务端 run 内状态和实际工具调用决定，不能只检查提示词 UUID、
顶层最终消息或模型自述。状态应跨父子图、工作线程和并行分支传播，
run 之间隔离；观察状态缺失或不确定时禁止写缓存。工具失败、预算拒绝、
取消、超时及部分结果均不可写成成功缓存。
新缓存命中仍在既有授权、输入/输出校验、租约与 deadline 合同内处理。

这项修改仅针对 FastAPI REST 回答缓存。LangGraph 主聊天不使用该缓存，
其历史消息继续按 R4 的计算时快照处理，不对外宣称“自动擦除全部历史文件答案”。

#### 场景

- **当**同一用户重复文件查询，且文件已经删除/过期/漂移，**则**重新执行当前文件检查，
  不返回旧缓存；未出现显式引用但实际执行了文件工具的调用同样不得写缓存。
- **当**子图或并行分支执行任何工具，**则**顶层结果不能因只剩最终文字而误获缓存资格。
- **当**相同普通问答完全没有工具执行，**则**可命中新策略缓存且不能跨主体复用。

### R6 缺失工具结果不得合成为成功

修正 `ensureToolCallsHaveResponses`：按各次 AI 工具调用的 `tool_call_id`
检查对应后续工具结果，不能以“下一条恰好是任意 tool 消息”认定整组完成。
已有真实结果原样保留；重复执行补齐不得重复追加，乱序、多工具和部分返回均需覆盖。

只有缺失项需要协议补齐时，使用支持的 error/未完成状态及中性说明，
明确“没有取得工具结果”；不得臆测是用户取消、伪造执行成功或生成统计 payload。
缺失调用 ID 不能创建空 ID 成功消息；使用稳定提示阻止不合法续发，
保留用户输入，待重试/恢复后继续。仅修对应提交路径，不扩展为整个 Cancel 或附件编辑重构。

#### 场景

- **当**三项调用只有两项真实结果，**则**仅缺失项获得未完成说明，其他结果不改写。
- **当**用户在失败或断流后再次发送消息，**则**模型收到真实结果和明确的未完成信息，
  不再收到伪造的 “Successfully handled tool call.”。

## 移除要求

不移除公开接口、上传格式或历史数据。废止缺失工具结果默认补“成功”的内部行为；
旧消息保持，只约束后续补齐。缓存策略升级仅使旧命名空间自然失效，不迁移其答案。
