# 恢复内容准入修复

2026-10-28；承接“继续修复和迭代”，基线 `c732275`。
本轮只收紧既有格式 1 的恢复准入；保留历史门禁、tasks/checklist 和失败记录。

## 问题与目标

归档现有校验逐项检查路径和类型，但没有拒绝重复路径、规范化后重名、
文件/目录父子冲突；JSON 重复字段被默认解析器覆盖。
这些归档在重算 manifest hash 后可以通过验证，进入后续恢复流程。
外层 restic helper 还需要保证清单不符或快照夹带额外文件时，最终目标保持不存在。

## 合同

- 格式 1 固定四个文件；清单、artifact 元数据与数字类型严格校验，
  重复 JSON 字段拒绝。三个域的内容 hash、依赖锁、revision/源码兼容条件保留。
- 只接受现有生产器生成的不压缩 tar；归档根目录 `.` 合法。
  拒绝符号/硬链接、特殊条目、重名及文件/目录冲突，不依赖提取工具的覆盖顺序。
- 清单上限 64 KiB；三个域总字节及解包总文件字节各不超过 1 GiB，
  每个 tar 不超过 100,000 个条目。限制在读取大量内容或调用 Docker 前生效。
- 下载必须先校验完整 snapshot 条目清单，仅接受同一目录下的四个固定文件及其
  祖先目录。按可信 manifest hash 检查文件尺寸与内容，使用有界流逐文件下载，
  不提取 snapshot 自带路径。
- 临时目录权限限制为当前执行主体，最终目标只在全部校验通过后出现；
  目标必须不存在。失败清除本轮 staging，既有目标不改动。
- 限制保护意外损坏和不合规备份，不把本机同权限恶意进程的任意改写描述为已解决；
  工作目录、目标父目录和可信 manifest hash 仍须由操作方控制。

## 验证

先红后绿的恢复调用点测试；真实本地 restic 加密仓库的错误清单、夹带文件、
字节上限、已有目标、下载中断及正常四文件回环；历史支持检查回归。
核心归档测试进入现有仓库 pytest。外层支持脚本及可重复回归入口位于工作区根。
不因本轮成功声称生产 Agent Server、自动异地备份或真实模型效果已通过。
