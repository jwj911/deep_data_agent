# 验收清单

- [x] 系统只定义 `user`、`admin` 两种角色，角色权限矩阵集中维护且不允许请求方自定义权限。
- [x] 未知角色、未知权限或缺失映射均默认拒绝，不执行受保护的数据查询或写入。
- [x] `users.role` 在 ORM 中非空，应用默认值和数据库默认值均为 `user`，并具有固定值约束。
- [x] Alembic 线性迁移可将包含既有用户、会话和消息的数据库升级到新 head；原数据不变且既有用户回填为 `user`。
- [x] 空库升级、迁移降级、单 head 和 ORM metadata 无漂移测试通过，SQLite 与 MySQL 迁移语义一致。
- [x] 公开注册接口不接受角色输入；新注册用户固定为 `user`，额外字段不能造成权限提升。
- [x] 注册和 `/api/auth/me` 返回合法 `role`；前端 `AuthUser` 只接受 `user` 或 `admin`，且不在浏览器端替代服务端授权。
- [x] RBAC 保护的操作在路由依赖与服务方法中分别检查权限，服务直调不能绕过授权。
- [x] `user` 对本人会话的读、写、删行为保持兼容，既有认证和所有权语义不回归。
- [x] `admin` 仍只能访问本人会话；读取、写入或删除他人会话与不存在资源一致返回 `404`，数据不变。
- [x] 未登录访问管理员端点返回既有稳定 `401`，不泄露角色或目标资源信息。
- [x] 已认证 `user` 访问任意管理员端点返回稳定 `403`（`code=forbidden`），且拒绝发生在目标用户查询之前。
- [x] `GET /api/admin/users` 仅允许管理员访问，按用户 ID 稳定排序，`offset` 非负且 `limit` 限定为 `1..100`。
- [x] `PATCH /api/admin/users/{user_id}/role` 仅接受固定角色，可事务化修改他人角色，并对重复设置保持幂等。
- [x] 管理员修改自己的角色返回稳定 `409`（`code=self_role_change_forbidden`），数据库不发生变化。
- [x] 已授权管理员修改不存在的目标返回稳定 `404`（`code=user_not_found`）；未授权调用方不能据此探测目标。
- [x] 角色变更后无需重新签发 JWT；后续请求通过数据库中的最新角色立即获得或失去权限。
- [x] `scripts/bootstrap_admin.py --user-id <id>` 只接受正整数 ID，只能提升既有用户，重复执行幂等，失败返回非零且不输出敏感信息。
- [x] 不存在按用户名、邮箱、注册字段或普通环境变量自动提升管理员的路径，发布契约可阻止默认管理员回归。
- [x] 管理员列表、角色变更和人工引导均产生固定结构化审计事件；成功变更记录操作、结果和前后角色。
- [x] 授权拒绝与 `ENABLE_CODE_EXECUTION=true` 下的高风险工具注册产生固定审计事件，不记录目标存在性或工具输入。
- [x] 审计身份使用服务端密钥派生的稳定 HMAC actor/target 引用；日志不含原始用户 ID、用户名、邮箱、IP、Token、密码、请求体、查询参数或连接串。
- [x] 审计事件使用 UTC、固定事件名和字段白名单，并在 HTTP 上下文中携带合法请求 ID；诊断导出不会绕过脱敏。
- [x] CORS 白名单允许 `PATCH` 及既有认证/请求 ID 头；管理员路由受默认限流和 HTTP 观测保护，`/api/health` 行为不变。
- [x] 后端 pytest/isort、迁移与发布契约、Compose 解析、`git diff --check`、前端 typecheck/lint/format/build 全部通过；README、AGENTS、项目分析、Roadmap、CHANGELOG 与实现一致，工作区不含凭据、业务数据、构建残留或无关改动。
