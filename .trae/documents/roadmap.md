# Deep Data Agent Roadmap

> 状态日期：2026-08-10。Roadmap 是候选迭代顺序，不是自动执行授权。每轮迭代
> 必须由人工明确触发，并在开始前确认输入、日志、测试数据和产物均已脱敏。

## 决策原则

- 先完成发布治理，再扩展业务能力；未通过当前门禁的变更不得进入下一阶段。
- 观测性优先于高并发、权限扩展和数据分析，以便新能力具备可定位的失败证据。
- 真实 API Key、JWT、密码、Token、业务数据和可识别用户信息不得进入规格、
  提示词、测试固件、CI 日志或版本控制。
- 高风险操作，包括代码执行、历史重写、生产数据验证和模型批量调用，必须人工
  二次确认；默认关闭，不设计自动触发链路。
- 每项候选只有在依赖满足、进入条件成立并经人工评审后，才能转为正式 Spec。

## 后续候选

### 1. 请求限流与资源保护

- **依赖**：观测性基线、稳定用户身份、Redis 可用性和容量基线。
- **进入条件**：按匿名来源、用户和高成本工具定义配额；确定 Redis 故障时的
  fail-open/fail-closed 策略及可信代理边界。
- **验收门槛**：限流响应和重试语义稳定；并发与突发测试覆盖绕过、时钟和缓存
  故障；不同用户计数隔离；日志与指标不记录原始 Token、提示词或业务数据。

### 2. RBAC 与审计

- **依赖**：第一方认证、版本化数据库迁移、观测性和请求限流。
- **进入条件**：角色、权限、资源和管理员操作矩阵经人工安全评审；最小权限与
  默认拒绝策略明确。
- **验收门槛**：路由和服务层同时执行授权；水平与垂直越权测试通过；角色变更、
  高风险工具启用和管理操作有脱敏审计记录；无权限响应不泄露资源存在性。

### 3. 版本化数据库迁移

- **依赖**：发布 CI 和可恢复的数据库备份流程。
- **进入条件**：选定迁移工具，盘点当前表结构，并验证开发、测试和 Compose
  数据库的基线版本。
- **验收门槛**：全新安装和已有数据升级均可重复执行；升级失败可恢复；CI 校验
  migration head；任何结构变更不再依赖仅运行 `create_all()`。

### 4. 数据分析与报告能力

- **依赖**：观测性、限流、RBAC、版本化迁移，以及文件和代码执行的隔离方案。
- **进入条件**：定义支持的数据格式、大小限制、保留策略、脱敏规则和租户边界；
  明确图表、分析和报告的可追溯输入输出契约。
- **验收门槛**：导入、分析、可视化和报告全链路使用专用脱敏数据通过；文件类型、
  大小、公式注入、路径访问和资源消耗受到限制；结果可关联来源与版本；代码执行
  在沙箱缺失时保持关闭；任何真实业务数据验证均由授权人员人工触发。

## 路线调整规则

出现安全回归、门禁失败、凭据泄露、跨用户访问或无法脱敏的诊断数据时，暂停后续
候选并回到发布治理。候选优先级的调整必须更新正式 Spec、Roadmap 和变更记录，
不得仅通过实现代码或自动化 Agent 隐式改变范围。
